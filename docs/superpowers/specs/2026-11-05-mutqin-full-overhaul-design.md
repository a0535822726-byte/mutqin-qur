# مُتقن — التصميم الشامل للتطوير

## الهدف
تحويل مُتقن إلى تطبيق قرآني عربي متكامل للتلاوة والحفظ والمراجعة والتجويد، بواجهة جديدة واضحة، مع وظائف حقيقية قابلة للاختبار، يعمل على Android 15 وما قبله ضمن حدود المشروع الحالي.

## ما يريده المستخدم
- إعادة تصميم الواجهة الرئيسية والشاشات الأساسية بالكامل، مع الحفاظ على الهوية الخضراء والذهبية.
- أقسام مستقلة لكل أداة، لا بطاقات مكررة ولا أزرار شكلية.
- جعل التسميع الصوتي محورًا رئيسيًا: اختيار السورة والآيات، تسجيل، استماع، حفظ الجلسات، وعرض النص الملتقط ومقارنته بالنص المرجعي.
- دروس وتمارين تجويد منفصلة، مع توضيح حدود التحليل الآلي وعدم الادعاء بقياس المخارج أو الغنة أو المد ما لم يوجد محرك متخصص موثوق.
- توسيع أدوات الحفظ والمراجعة والبحث والتخطيط والمتابعة، مع حفظ التقدم محليًا.
- واجهة عربية RTL، ودعم الوضعين الفاتح والداكن، وتجربة مناسبة لشاشة الهاتف.

## النطاق
### ضمن هذا المسار
1. إعادة تصميم لوحة البداية والتنقل وتصنيف الأدوات.
2. تحسين تدفق جلسة التسميع والتسجيل والاستماع وإدارة الجلسات.
3. مقارنة نص التعرف الصوتي بالآيات مع تمييز الكلمات المتطابقة/المختلفة دون اعتبارها حكمًا شرعيًا أو تقييمًا تجويديًا.
4. توسيع التدريب التعليمي للتجويد والاختبارات مع تغذية راجعة واضحة.
5. مراجعة كل بطاقة/زر في الصفحات التي تمسها التغييرات وربطها بوجهة حقيقية.
6. إضافة اختبارات منطقية للمعالجة النصية والمقارنة وحالات الإدخال.
7. بناء APK عبر GitHub Actions وفحص نجاحه قبل مشاركة الرابط.

### خارج النطاق أو مشروط
- لا نعد بتصحيح صوتي حقيقي لمخارج الحروف أو الغنة أو مقادير المد اعتمادًا على Android SpeechRecognizer وحده.
- لا نرسل التسجيلات إلى خادم أو خدمة خارجية دون إعداد واضح وموافقة صريحة من المستخدم.
- لا نضيف خدمات مدفوعة أو مفاتيح سرية أو اشتراكات افتراضيًا.
- لا نحذف بيانات المستخدم المحلية أو نكسر التوافق مع تقدم النسخ السابقة عمدًا.

## قرارات التصميم
- التصميم: لوحة رئيسية تحريرية مع شريط ترحيب، إجراء أساسي للتسميع، بطاقات فئات، وبحث سريع عن الأدوات.
- التسميع: فصل التسجيل عن التعرف على الكلام؛ التسجيل محلي، والتعرف الصوتي عملية مستقلة قد تتطلب اتصالًا وخدمة مثبتة.
- النتائج: إظهار النص المرجعي والنص الملتقط، مع تطابق تقريبي للكلمات وملاحظات حدود الدقة.
- التجويد: وحدات تعليمية واختبارات منفصلة، مع تنبيه أن تقييم النطق الصوتي يحتاج معلّمًا أو نموذجًا متخصصًا تم التحقق منه.
- التخزين: استخدام AppPrefs الحالية للبيانات البسيطة، وتجنب إدخال قاعدة بيانات/خدمة سحابية في هذه المرحلة.
- التقنية: Kotlin + Jetpack Compose + Android APIs الحالية، دون إضافة مكتبات خارجية إلا لضرورة موثقة.

## اعتبارات الجودة والسلامة
- لا يتم تصنيف قارئ القرآن أو منحه درجة تجويد مضللة من التعرف الصوتي العام.
- عرض أخطاء التعرف المحتملة بوضوح، وإتاحة إعادة المحاولة.
- التحقق من أرقام السور والآيات، والأذونات، وفشل التسجيل، وغياب خدمة التعرف.
- واجهة قابلة للوصول: تباين جيد، أهداف لمس كبيرة، تسميات مفهومة، وحالات خطأ واضحة.

## طرق التنفيذ المدروسة
1. إعادة كتابة التطبيق كله دفعة واحدة: تغييرات واسعة ومخاطر عالية على الميزات الحالية.
2. تطوير مرحلي على فرع مستقل: إعادة بناء لوحة البداية وتدفق التسميع أولًا، ثم فحص البناء، ثم توسيع بقية الأقسام. **هذا هو الاختيار المعتمد** لأنه يحافظ على العمل الموجود ويسمح بالتحقق من كل مرحلة.
3. إضافة خدمات سحابية لتحليل التلاوة فورًا: مستبعد الآن بسبب الحاجة إلى خدمة متخصصة موثوقة، وإعدادات خصوصية وتكلفة وربط حسابات.

## معايير القبول
- كل بطاقة رئيسية تفتح شاشة فعلية.
- لا يوجد زر يبدو فعالًا دون فعل أو حالة معطلة موضحة.
- لا تضيع الجلسة الصوتية الحالية عند إعادة تركيب الشاشة، وتظهر رسائل واضحة لفشل الحفظ أو التشغيل.
- مقارنة النص لا تدعي أنها تصحيح تجويد.
- تنجح اختبارات منطق المقارنة والتحقق من المدخلات.
- ينجح بناء APK في GitHub Actions، ويُفحص سجل البناء قبل إعلان الجاهزية.
